# The example host

The integration guides all use one host, so a snippet you meet halfway down a
page resolves without back-reading. This page is that host. (`ARCHITECTURE.md`
is the exception: it illustrates manual and OpenAPI registration with a
separate minimal example.)

## The Bharat Times

The Bharat Times is our own fictional demo newsroom. It runs on Payload CMS,
with a Next.js front end and Postgres behind it. Everything it publishes —
articles, the sections they are filed under, short facts, puzzles, reader
polls, and the picture library — sits behind one GraphQL endpoint at
`/api/graphql`, generated by the CMS. Two surfaces read it: the public site
anyone browses, and an **Ask** page at `/ask` where a reader types what they
want and gets a composed view back.

The Ask page is what the guides build. The paper has no data team, and its
readers' questions are the kind nobody builds a page for in advance:

> "Show me the latest politics coverage."
> "How many articles have you published in total, and show me the latest sport stories."
> "List the articles from oldest to newest."
> "Show me the easy puzzles only."

## The API

Payload generates far more root fields than a newsroom needs — user records,
document-access checks, version history, form submissions, more than eighty in
all. The paper approves seven:

| Root field   | Returns            | Capability                     | Shape            |
| ------------ | ------------------ | ------------------------------ | ---------------- |
| `Posts`      | page of `Post`     | `bharat-times.posts.list`      | collection       |
| `countPosts` | `{ totalDocs }`    | `bharat-times.posts.count`     | metric           |
| `Categories` | page of `Category` | `bharat-times.categories.list` | collection       |
| `Facts`      | page of `Fact`     | `bharat-times.facts.list`      | collection       |
| `Puzzles`    | page of `Puzzle`   | `bharat-times.puzzles.list`    | collection       |
| `Polls`      | page of `Poll`     | `bharat-times.polls.list`      | collection       |
| `allMedia`   | page of `Media`    | `bharat-times.media.list`      | media-collection |

Every capability is public: the paper publishes nothing a reader may not see,
so none of them takes an identity from the session. The `draft` and `trash`
arguments on every list are not approved because they expose
unpublished and soft-deleted content, and the free-form `where` filter object.

Every list uses `limit`/`page` arguments and returns rows in an object. That wrapper
is what the guides declare as a `listEnvelope`, and it is why every approved
field path is row-relative — `title`, never `docs.title`.

```graphql
type Posts {
  docs: [Post!]!
  totalDocs: Int!
  hasNextPage: Boolean!
  page: Int!
  limit: Int!
}

type Query {
  Posts(limit: Int, page: Int, sort: String, where: Post_where, draft: Boolean, trash: Boolean): Posts
  countPosts(where: Post_where, draft: Boolean, trash: Boolean): countPosts
}

type Post {
  id: Int!
  title: String
  slug: String
  publishedAt: DateTime
  heroImage: Media
  categories: [Category!]
  meta: Post_Meta          # meta.description carries the standfirst
  _status: Post__status    # published | draft
}

type Category   { id: Int!  title: String!  slug: String!  parent: Category }
type Fact       { id: Int!  text: String!   attribution: String }
type Puzzle     { id: Int!  title: String!  type: Puzzle_type!  difficulty: Puzzle_difficulty  publishedDate: DateTime! }
type Poll       { id: Int!  question: String!  options: [Poll_Options!]!  isActive: Boolean }
type Media      { id: Int!  url: String  alt: String  filename: String  width: Float  height: Float }
type countPosts { totalDocs: Int }
```

Two things about this schema shape the examples. `sort` is a bare `String` —
Payload spells newest-first as `"-publishedAt"`, so the guides declare that
grammar as an `orderingArgument`. Payload also
Payload emits its enums and filter inputs as custom scalars (`DateTime`,
`Post__status`, `Post_where`), so the catalog carries a `scalarMappings` entry
for every one that is reachable.

The sections are Politics, Business, World, Opinion, Culture, and Sport. The
catalog id is `bharat-times`; the source id is `bharat-times-cms`.
